# Reproducing PATHS

All mathematical programs used for the reported finite checks are included here, together with their recorded outputs. Python 3 is sufficient for Parts A, B and D. Part E additionally needs SymPy. The build uses LuaLaTeX and BibTeX with `natbib`, `apalike`, Latin Modern, AMS packages, `mathrsfs`, `longtable`, `hyperref`, `microtype`, `geometry`, `enumitem`, `fancyhdr` and `bookmark`. The mathematical checks make no network calls.

## Independent finite computations

Run these commands from the `PATHS` directory. Each command writes the output file distributed with the package.

```bash
python code/a_finite_checks.py > code/a_finite_checks_output.json
python code/b_path_search.py --length 3 > code/b_path_search_L3.jsonl
python code/b_path_search.py --length 4 > code/b_path_search_L4.jsonl
python code/b_crown_checks.py > code/b_crown_checks.txt
python code/d_finite_checks.py > code/d_finite_checks.txt
python code/e_finite_checks.py > code/e_finite_checks.out
```

The final command also writes `e_category_tables.json`, containing the full finite category composition tables for the sphere and pushouts, and the rectangular-band multiplication table. The Part B length-four search processes over 2.5 million nondegenerate two-simplices in its largest case and can take substantially longer than the other checks. Its output is a bounded search, not evidence of stabilization of the infinite path category.

`a_finite_checks.py` enumerates the 456 reverse subdivision maps, checks `C2` and the indicated truncated `Delta_inj` representable homology diagrams. `b_crown_checks.py` checks the four-object covering example and its finite ladders. `d_finite_checks.py` contains the five-arrow pointed category, intrinsic-cofibration lattice enumerations, circle endomorphisms, nine-fence horn, finite-shape failure of test (b), Nielsen matrix and the complete `S3` obstruction. `e_finite_checks.py` checks the lift obstructions, idempotent and rectangular-band monoids, actual sieve pushouts, category axioms and normalized-chain homology ranks. The proofs in the paper handle each infinite quantifier separately.

## Register and bibliography

```bash
python code/a_build_register.py > code/a_build_register_output.txt
python code/ce_build_register.py > code/ce_build_register_output.txt
python code/d_build_results.py > code/d_build_results_output.txt
python code/assemble_package.py > code/assemble_package_output.txt
```

The Part B result metadata are explicit JSON rather than generated by a separate script. Assembly verifies a one-to-one correspondence between the 76 result environments and CSV rows, matching status labels, all bibliography keys and all appendix statement links. It consolidates aliases of the same bibliography entry while retaining each verification scope. It writes `audit/assembly_check.json`.

## Paper build

On an ordinary TeX Live installation:

```bash
python code/build_paper.py > audit/build_output.txt 2>&1
```

Equivalently, run LuaLaTeX, BibTeX, then LuaLaTeX twice on `PATHS_paper`. The master TeX file inputs all section files in this package. The bibliography uses author–date citations and the APA-like BibTeX style. DOI/URL fields and detailed verification notes remain available in `PATHS_references.bib` even when the style does not print every field.

The supplied execution container had the TeX package trees and LuaHBTeX engine but lacked the system format/index configuration and OpenType font loader. The paper uses Type 1 Latin Modern fonts, so the optional command below builds a local format with that font configuration and reconstructs the necessary font map. It edits no system files and requires no network or package installation:

```bash
python code/build_paper.py --local-tex-runtime > audit/build_output.txt 2>&1
```

The local format and cache are reproducible intermediates and are excluded from the ZIP. The final LuaLaTeX and BibTeX logs are retained in `audit/`.

## Source-dependent audits

These two programs use the separately supplied original source archive and its extraction, which are not redistributed here. Run them from the parent workspace containing `PATHS/`, `sources/` and the original `upload/` directory:

```bash
python PATHS/code/source_integrity.py > PATHS/code/source_integrity_output.json
python PATHS/code/b_reference_audit.py > PATHS/code/b_reference_audit.txt
```

The first verifies all 222 hashes in the supplied manifest against both archive bytes and extracted bytes. The second checks Arakawa–Cnossen theorem numbering against the supplied TeX source and summarizes both path-search outputs. Their recorded outputs are included, so rereading the source corpus is not required to inspect the reported checks.

## Final assembly and layout checks

`build_report.py` assembles the standalone report from the main report text and the detailed evidence records. `verify_delivery.py` checks final compilation diagnostics, PDF structure and page count, the result register, bibliography, and required package inputs. `render_qa.py` renders every PDF page and creates contact sheets for visual inspection; those page images are reproducible inspection intermediates and are not distributed. It replaces prior generated page and contact-sheet images in its output directory, which should be dedicated to this purpose. `make_zip.py` builds the final archive with a SHA-256 inventory of its contents and checks every inventory entry, the exact file set, and ZIP CRCs. Their outputs are retained in `audit/` or `code/` as applicable.
