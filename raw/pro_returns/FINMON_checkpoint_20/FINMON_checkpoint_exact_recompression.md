# Exact-byte transfer encoding

Every original logical file is preserved with its original complete SHA256. For source-linked JSONL certificates, only the 64 ASCII hexadecimal characters of each source-line hash are omitted from the stored representation; they are recomputed from the complete referenced source row. Every omitted hash was checked before encoding, and each whole original certificate file was regenerated and independently SHA256-checked. All other certificate characters, row numbers and proofs are literal original bytes. Other permitted encodings retain original gzip/PNG headers and exact compression parameters. Identical encoded bytes can serve several manifest paths. Raw XZ storage decodes directly to the original file bytes. Shared PNG encodings store concatenated original scanline buffers with explicit offsets, and each original PNG is regenerated byte for byte. A frozen prefix of a running GNU gzip stream may use a completed stream as its compression-state basis; restoration stops at the exact frozen byte length and checks the original prefix SHA256. Additional basis bytes are never restored as scientific payload. Completed category gzip certificates may derive their row number, object count, source labels, target labels and full multiplication string from the preserved literal source table. Every omitted field is checked during encoding and the entire original gzip is regenerated and SHA256-checked. No other certificate character is changed. Literal JSON column transposition preserves every value byte, key, field order and line ending before regenerating the exact original GNU gzip prefix. For a frozen unfinished deflate block, a stored literal compressed suffix is appended to the regenerated stable prefix; their combined original bytes and SHA256 are checked. Shared text dictionaries retain each original file as a literal byte slice, with offsets, sizes and independent original hashes. HDF run encodings retain every non-chunk byte, the decoded chunk runs and original Fletcher32 trailers; zlib level9 regenerates each original compressed chunk, and full original SHA256 is required. Source-derived ZIP encoding retains the original deflate Huffman headers, match instructions, extra and padding bits; literal bytes come only from separately retained SHA256-identified members. No original ZIP metadata or compression bit is changed. Self-contained deterministic C++ stdout recipes contain every compiler source and every input-data byte. They reconstruct the original stdout and literal Python/zlib gzip with its original header, CRC and length. Each entire original compressed file must be regenerated and SHA256-checked before the recipe is eligible. The archive verifier either repeats that full regeneration or explicitly records reuse of a pinned completed full regeneration after matching every actual encoded byte, every decoding metadata field, the audited decoder and the full original size/SHA256. A separate prefix-recipe encoding reconstructs every byte of a frozen unfinished gzip prefix, then deliberately closes the remaining generator. It makes no producer-completion or census-completion claim. Its entire original prefix is regenerated and SHA256-checked before eligibility. Archive verification either repeats this exact prefix regeneration or explicitly records reuse of a separately pinned completed prefix proof after checking every actual encoded byte, all decoding metadata, original size/SHA256 and both audited decoder sources, including the exact known standalone import rewrite. Generic baseline reuse remains forbidden for prefix recipes. Complete per-profile source-table gzips may use exact row transposition before their original Python/zlib compression is reconstructed. Source-dependent certificates consume only the fully regenerated, SHA256-checked original source gzip bytes; sources are restored before dependent certificates. Eligible contact PNGs are reconstructed from fully retained original page PNGs using fixed layout parameters and embedded exact font bytes. Every dependency and the complete original contact PNG must match their original size and SHA256; incompatible Pillow/FreeType/zlib reconstruction fails closed. Literal or exact scanline-encoded page sources are verified before use, and restoration schedules all page sources before contacts. Some small literal gzip members use ZIP-LZMA only as the outer ZIP compression method; extraction returns every original gzip byte unchanged, and their logical records have no archive encoding. These records require g++ with C++17 support and compatible Python/zlib; reconstruction can take several minutes. The original snapshot and original helper files remain unchanged. Current helpers are added at the archive root.
