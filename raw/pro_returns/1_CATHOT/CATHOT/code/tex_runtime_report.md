# Genuine LuaLaTeX runtime repair

## Build command

From the conversation workspace root:

```bash
python CATHOT/code/run_with_tex.py
```

This runs the existing `CATHOT/code/build.py` unchanged with the workspace TeX environment. It uses `/usr/bin/lualatex`, which identifies itself as **LuaHBTeX 1.18.0 (TeX Live 2025/dev/Debian)**. There is no substitution of XeLaTeX, pdfLaTeX, or Tectonic.

To run an individual tool under the same environment, put its command after the wrapper, for example:

```bash
python CATHOT/code/run_with_tex.py kpsewhich apacite.bst
```

To reconstruct the workspace dependencies and format after deletion:

```bash
python CATHOT/code/setup_lualatex.py
```

The setup command requires the installed TeX engine and installed TeX trees already present on this machine, and network access to a CTAN mirror for missing packages. It performs no system installation.

## Causes and repairs

1. The installed TeX trees existed but their filename databases and generated formats were absent. Default `TEXMF` marked the trees with `!!`, which permits database lookup only. Thus `kpsewhich` could not locate even the existing `latex.ltx`. The workspace `TEXMF` omits `!!` and permits ordinary filesystem lookup in the installed trees.
2. LuaOTFLoad, Lua libraries, and several supporting packages were absent. The setup script fetched the TeX Live runtime archives `lualibs`, `luaotfload`, `luatexbase`, `lua-uni-algos`, and `apacite` from CTAN mirrors, extracting regular files only into the workspace TEXMF. Exact download URLs, lengths, and SHA-256 hashes are in `setup_lualatex.out`.
3. The actual `lualatex.fmt` was generated by the installed LuaLaTeX engine in initialization mode, using the installed `lualatex.ini` and `latex.ltx`. The complete initialization log is `tex_format_build.out`.
4. The generated `pdftex.map` was absent. The setup combines the existing installed Computer Modern, AMS, Euler, and Latin Modern map entries into a workspace map; it neither edits fonts nor substitutes their mathematical glyphs.
5. LuaTeX's `openout_any=p` protection initially prevented absolute font-cache writes. `TEXMFOUTPUT` now designates the workspace runtime root as an allowed output root. The protection remains enabled; no `openout_any=a`, sandbox escalation, or HOME change was used. `tex_cache_probe_engine_fourth.out` confirms writes succeed under the actual LuaHBTeX engine.

The exact environment is saved in `tex_environment.json`. Its variables are `TEXMFHOME`, `TEXMFVAR`, `TEXMFCONFIG`, `TEXMFCACHE`, `TEXMFOUTPUT`, `TEXMF`, and `TEXFORMATS`. They all refer to workspace paths except for the existing read-only installed TeX trees.

## Validation and source boundary

With these repairs, LuaLaTeX loaded LuaOTFLoad, fontspec, the OpenType Latin Modern fonts, and the installed CM/AMS math fonts. It rendered the paper's first two pages and then reached a source-level `Double subscript` error at `sections/A.tex`, line4, caused by appending a universe subscript to the macro `\Cathot` whose expansion already has a subscript. That error was reported to the parent author for correction. No mathematical or typesetting source was edited as part of the runtime repair.

The original missing-format failure remains in `build.out`. The first runtime cache failure remains in `build_bootstrapped.out`; the subsequent source-level failure is in `build_bootstrapped_second.out`. The wrapper archives prior per-pass logs and the paper log under `code/build_history/` before a default build, so later passes do not erase them. Additional diagnostic Lua/TeX programs and their run outputs are saved beside this report.

## Packaging

Downloaded packages, formats, and font caches are in the **sibling directory `tex_runtime/` outside `CATHOT/`**. At initial validation it occupied approximately 22MB. Exclude that sibling runtime from the deliverable ZIP; keep the setup programs, environment record, and logs under `CATHOT/code/`. Python `code/__pycache__/` is generated cache and can also be excluded.

`apacite.bst` is now available, but the manuscript's existing natbib/apalike choice was left unchanged as instructed. No remaining runtime dependency was missing at the point the first source-level error was reached.
